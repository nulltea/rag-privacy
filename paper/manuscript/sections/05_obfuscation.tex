\section{Static Obfuscation}
\label{sec:obfuscation}

% --- scope-framing (short role-framing) ---
Static obfuscation transforms the data and/or weights so the server sees only values it
cannot interpret~\citep{lin_aloepri,roberts_sgt}, with no trusted hardware or only a minimal amount. It is the cheapest
family in our taxonomy: cost is near-plaintext and no trusted hardware is required (Tier~1).
That low cost is also why its privacy claims deserve the most scrutiny. The obfuscation is
\emph{fixed}, and the adversary is the white-box server. It knows the obfuscation algorithm
and its parameters, and it can passively collect the intermediary results of its own
computation and use them to train an inverter model. On the deployment-readiness criteria,
obfuscation leads on performance and is often near-lossless. Accuracy is not uniform across
the family, however, and depends on how hard each scheme tunes its hiding
(\cref{sec:obfusc-perf}).

A second advantage is infrastructural. These schemes leave the model architecture intact, so
they fit standard inference stacks far more readily than crypto or hybrid schemes, which require
a custom serving path. The deployment
trade-offs, including who must perform the one-time obfuscation and hold the secret, are
examined in \cref{ssec:deployment}.

\subsection{Approaches}
In every scheme the client applies a secret transform so the server computes on values it cannot
interpret, then de-obfuscates the result. They differ in \emph{what} they transform. Most either obfuscate the model weights (AloePri,
ObfusLM, KV-Cloak) or transform only the input embeddings and run on a stock, unmodified
model (SGT, OSNIP, Eguard); CodeCipher is a domain-specific outlier for source code. In the \cref{sec:framework} taxonomy the trusted core
is none or light (Tier~1, at most a TEE holding keys), and the adversary is an
honest-but-curious, white-box operator. The observation surface is everything the scheme
offloads to the untrusted accelerator: the obfuscated input and output, and, depending on the
scheme, the offloaded attention and externalized KV-cache, plus the intermediate activations
of the offloaded matrix multiplications.

\textbf{ObfusLM}~\citep{obfuslm} permutes and re-synthesizes the vocabulary, embedding, and
head under a \emph{provable} $(k,\varepsilon)$-anonymity guarantee (cluster size $k$, DP
budget $\varepsilon$). This is a formal footing that is rare in this otherwise heuristic
family. Because the vocabulary itself is permuted, it protects the \emph{generated output} as
well as the input, at the cost of fine-tuning the model on the obfuscated embeddings before
serving. \textbf{AloePri}~\citep{lin_aloepri} is its covariant successor. It carries the
secret token permutation beyond the embedding and head into the \emph{remaining} weights,
using invertible matrices and additive Gaussian noise, so the server runs stock inference
with no fine-tuning. The client de-obfuscates the permuted response, so AloePri protects the
output as well. Its hiding strength is governed by several secret parameters, not one: a
keymat expansion $h$ that widens the residual stream to $d_{\text{obs}}{=}d{+}2h$, the scale
of the additive Gaussian noise, and a per-head permutation window. Each trades accuracy for
hiding. The expansion in particular makes the obfuscation matrices more ill-conditioned,
which amplifies floating-point error layer by layer and is what degrades accuracy at large
$h$ (\cref{sec:obfusc-perf}). \textbf{KV-Cloak}~\citep{luo_shadowcache} is narrower, securing only the KV-cache (the cached
keys and values that encode the prompt) against an attacker who reads the externalized cache,
e.g.\ via a GPU-memory leak. It transforms the cache as $K'{=}S\,\hat{P}\,(K{+}A)\,M$:
persistent invertible matrices $S,M$ fused offline into the attention weights, a one-time
permutation $\hat{P}$ refreshed per PagedAttention block, and a beacon mask $A$ that recovers
$\hat{P}$ without storing it. It is lossless and adds ${<}0.45\%$ to prefill, and, covering the cache
rather than the I/O channel, composes with an input/output scheme for end-to-end protection.
The secret matrices $S,M$ sit in a TEE for key custody, and attention runs on the GPU. KV-Cloak's
per-block refresh of $\hat{P}$ is the structural escape of \cref{sec:obfusc-attacks}, making it the
family's outlier and a bridge toward the hybrids of \cref{sec:hybrid}; it splits no computation,
though, so we treat it as an obfuscation scheme.

The input-transform schemes leave the weights untouched. \textbf{SGT}~\citep{roberts_sgt}
(Stained Glass) adds learned, input-conditioned Gaussian noise to the embedding sequence,
$\tilde{x}{=}x{+}\mathcal{N}(\mu_\theta(x),\Sigma_\theta(x))$. The noise model is trained to
minimize the mutual information between the clean and obfuscated embeddings, which by a
PAC-Privacy bound limits how much observing $\tilde{x}$ helps an adversary reconstruct $x$,
while a separate utility loss keeps the frozen model's output unchanged.
\textbf{OSNIP}~\citep{cao_osnip} projects the input embedding onto an obfuscated semantic null
space, near-orthogonal to the recoverable subspace, using a client-side encryptor network
trained against the server LLM. \textbf{Eguard}~\citep{eguard} trains a projection network
with a dual-level mutual-information objective aimed explicitly at Vec2Text
inversion~\citep{vec2text}, driving inversion $F_1$ down to ${\approx}4\%$ while keeping
${>}98\%$ task accuracy. \textbf{CodeCipher}~\citep{codecipher} is domain-specific (coding). It trains, by discrete-gradient search (snapping each update to a valid token), a token-to-token confusion
map: a permutation of the embedding-matrix rows that replaces each code token with a different
one, minimizing task loss while raising obfuscation (perplexity and edit distance) so the
cloud LLM still returns the correct output. It is trained on a white-box proxy and transfers
to black-box LLMs.

Read off the headline columns of \cref{tab:inf-perf}, this family looks unambiguously cheap.
Every scheme runs at ${\approx}1\times$ plaintext and reports near-lossless accuracy. Both
numbers are \emph{sweet-spot} readings of a hiding knob that trades security, accuracy, and
performance against one another at the same time (\cref{tab:obfusc-tradeoffs}). The nuance the
headline hides is where each scheme pays.

\emph{Performance.} Online cost is genuinely small. KV-Cloak adds less than $0.45\%$ to
prefill, AloePri is near-zero, and the learned input transforms add only milliseconds
at the client. Eguard is the one exception at inference, because it runs its extra projection
network on every forward pass, for an inference overhead of about $1.7\times$. The larger
costs are \emph{offline}, and they split the family in two. The weight-transform schemes
(AloePri, KV-Cloak) need only a one-time transform of the weights, computed in minutes
with no training. The learned transforms instead pay a training bill, and in every case it is
a small add-on network trained on top of the frozen pretrained model, not the model itself.
SGT trains an input-conditioned transform over hours to days. OSNIP trains a client-side
encryptor. Eguard trains a 24-layer projection encoder, which makes each training step $1.6$
to $3.4\times$ slower than the same step without the defense. ObfusLM is the heaviest,
because it does not stop at an add-on: it fine-tunes the model itself on the obfuscated
embeddings, which the paper measures at over ten hours of server time, and the fine-tuned
weights are then tied to one checkpoint. The headline of near-zero \emph{inference} overhead
therefore hides a real setup cost for half the family. The infrastructural advantage is
real: every scheme but KV-Cloak runs on \emph{unmodified} inference software, pushing the
extra work to a client-side tokenizer or embedder. AloePri serves as a re-weighted checkpoint
on stock vLLM, and SGT, OSNIP, Eguard, and ObfusLM run the model unchanged while the client
supplies the obfuscated embeddings or token indices. KV-Cloak alone must insert obfuscation
operators into the attention path. None needs the custom serving runtime that crypto and TEE
schemes require.

\emph{Accuracy.} It is not free either, and the hiding knob is what sets it. KV-Cloak
is exactly lossless, because its matrices cancel in the attention product, so its accuracy is
independent of the security parameter. The other schemes face a privacy-utility curve. ObfusLM's $(k,\varepsilon)$-anonymity loses about $4\%$ on classification and about
$6\%$ on generation, and degrades further as the anonymity set $k$ grows. Eguard holds above
$98\%$ task accuracy, but only because its objective is tuned against inversion specifically.
AloePri is the most sensitive case, and its accuracy is not set by one parameter: the keymat
expansion $h$, the additive Gaussian noise, and the per-head permutation window all trade
accuracy for hiding. The expansion is the sharpest of them: a larger $h$ makes the obfuscation
matrices more ill-conditioned, so floating-point error is amplified through the model's depth
and accuracy falls off a cliff past a model-dependent value. AloePri's reported $0$ to $3.5\%$
loss is the reading at a tuned operating point, not a guarantee that holds as any of these
knobs is pushed for stronger hiding.

This sensitivity is itself a deployment factor, and it separates the family by \emph{how} the
hiding configuration is found. The training-free schemes
(AloePri, KV-Cloak) need no training, but a human must choose their hiding parameters for each
model, and a safe configuration is easy to miss. Such a scheme is only as strong as how well
that choice is formalized against the model's hyperparameters and the known attack vectors. A
well-formalized heuristic approaches an information-theoretic guarantee, but few schemes
formalize it, so the tuning is largely empirical today. The trained schemes (SGT, OSNIP,
Eguard, ObfusLM) instead let an add-on network learn the hiding, which removes the
manual-tuning risk but pays a heavy training cost and is itself retrained per model.

\begin{keyinsight}
In static obfuscation, performance, accuracy, and security trade off against one another. A
configuration strong on all three is attainable but non-trivial to find, and reaching it
usually costs ground on at least one axis. Locating that configuration is itself a cost: the
training-free schemes must choose their hiding parameters well, the trained schemes must train
an add-on network.
\end{keyinsight}

Static obfuscation applies one secret transform and reuses it on every request. The attacks here
are best read not as proof that obfuscation fails, but as a map of how hard each scheme has to work
and of where that work runs out. They fall into two kinds (\cref{tab:obfusc-attacks}). The first
kind a scheme can close or blunt with its own transform and knobs: a stronger, direction-changing
transform, more noise, a null-space projection, or inversion-hardened training. The second kind is
genuinely structural. Because the one secret is identical on every request, these attacks compound
across requests, and no setting of the knobs removes them; the only fix is to stop reusing the
secret, which moves a scheme out of the static family (\cref{sec:hybrid}).

\emph{Single-query inversion (mitigable).} The learned embedding transforms are invertible from
a single observation: the inversion attack on obfuscated embedding
matrices~\citep{lin_inversion} and nearest-neighbour attacks~\citep{kornaropoulos_knn_2019,naveed_ppe_2015}
recover tokens directly, and inversion succeeds even at deep and mid-level
layers~\citep{depth_false_privacy}. Here the family's knobs genuinely help: inversion-hardened
training (Eguard, $F_1{\to}{\approx}4\%$), a null-space projection (OSNIP), or a large anonymity
set (ObfusLM's $k$) materially reduce recovery. AloePri's evaluation still reports prior obfuscation schemes losing more than $30\%$ accuracy while leaking more than $50\%$ of
tokens, the trade-off the better-tuned schemes work to avoid.

\emph{Single-shot weight solving (mitigable by a strong transform).} With the weights observable, a
transform that only permutes or preserves vector directions is solvable from a single observation:
direction similarity alone recovers more than $98\%$ of such weights~\citep{arrowmatch}, and
vocabulary-matching and precomputed-noise attacks reconstruct the secret outright on the lightweight
schemes that leave directions intact (STIP, TransLinkGuard, SOTER, TSQP)~\citep{hnm,saini_precomp_break}.
The schemes we report defeat this because they do more than permute: AloePri wraps its permutation in
random invertible key matrices and additive noise, and ObfusLM in a $(k,\epsilon)$-anonymity synthesis,
which changes the very directions the attack relies on. The protection is heuristic, bought with
accuracy rather than proven, but it holds at the recommended settings, where AloePri recovers fewer
than $5\%$ of tokens~\citep{lin_aloepri,obfuslm}.

\emph{Accumulation under the reused secret (structural).} What no static transform closes is
accumulation. Because the secret is identical on every request, observations compound. Under a
static linear or orthogonal mixing the Gram matrix leaks the hidden-state covariance
($U^{\top}U{=}H^{\top}H$), and the fixed mixing makes blind source separation identifiable as
observations pile up~\citep{belikov_gelo,hyvarinen_ica,cardoso_jade}. A trained inverter learns the
inverse from the externalities the scheme offloads (hidden states, attention, KV-cache), all
produced under the one transform~\citep{geia,vec2text,depth_false_privacy}. The externalized
KV-cache is reconstructible by inversion, collision, and injection, and the collision attack defeats
a \emph{fixed} shuffle (KV-Shield) precisely because the shuffle is reused~\citep{luo_shadowcache}.
The deterministic token map adds a standing residual, leaking token frequencies like a substitution
cipher, which AloePri and ObfusLM suppress but cannot remove~\citep{lin_aloepri,obfuslm}.

\emph{The structural escape.} The accumulation channel, where a trained inverter or blind source
separation strengthens as observations pile up under the one secret, is closed only by
\emph{refreshing} that secret. Within this family only KV-Cloak does so, drawing a fresh permutation
per PagedAttention block, which is why it alone withstands the collision attack; the hybrid-split
schemes generalize the move with per-batch or per-offload refresh (\cref{sec:hybrid}).

\begin{openproblem}
\emph{Re-obfuscation scheduling.} A fixed secret is cheap, but under it a trained inverter and blind source separation only strengthen
as observations accumulate. Refreshing the secret resets that accumulation; refreshing on every
request removes it but is costly. \emph{Is there a refresh
period longer than a single request, yet short enough that neither attack succeeds within one
window, that holds recovery below a target at a fraction of the per-request cost?} A heuristic for the
re-obfuscation frequency that minimizes accumulation under a latency budget is an open problem.
\label{op:refresh-frequency}
\end{openproblem}
